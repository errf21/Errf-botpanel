## امکانات مشتری

| قابلیت | نحوهٔ کارکرد واقعی |
| --- | --- |
| **ثبت‌نام** | اولین آپدیت، سطر مشتری را آرام upsert می‌کند (پروفایل؛ `language` دست نمی‌خورد). |
| **منوی اصلی (reply keyboard)** | ۱۰ دکمه در ردیف‌های ۳/۲/۲/۳: ردیفِ اول = **سه استایل متمايز** 🔴🛒 خرید سرویس `danger`، 🔵📦 سرویس‌های من `primary`، 🟢💰 کیف پول `success` (همیشه کنار هم، هرگز جدا نمی‌شوند)؛ سپس 💳 سفارش‌ها، 👤 حساب، 🤝 دعوت، **🆘 پشتیبانی (تماس مستقیم، بدون تیکت)**، **🎫 ثبت تیکت (جریان قابل‌پیگیری)**، 📚 راهنما، 🌐 زبان. برچسبِ محلی، مسیریابی بین‌زبانی، **non-persistent و یک‌بارمصرف (one-time)** — هر فشردنِ دکمه، پنل را به نفع چتِ تمام‌صفحه جمع می‌کند و آیکون کیبورد کنار کادر نوشتن دوباره بازش می‌کند؛ پیام‌های راهنما هیچ کیبوردی نمی‌فرستند تا پنل خودبه‌خود برنگردد (`telegram/menu.ts`). |
| **خرید سرویس** | نام کانفیگ (متن آزاد sanitize یا `cfg:auto`) → حجم → مدت → تعداد کاربر → خلاصه → تأیید. preset و مقدار custom هر بار با کاتالوگ تازه اعتبارسنجی می‌شود. |
| **قیمت** | نمایش فقط مبلغ نهایی؛ لحظه‌ای؛ اسنپ‌شات روی سفارش. |
| **idempotency سفارش** | توکن ULID هنگام تأیید؛ دابل‌تپ‌/رپلی هرگز دو سفارش نمی‌سازد (۳ لایه). |
| **دستور واریز** | صاحب کارت + شماره کارت (inline-code کپی‌با-تپ)، IBAN (در صورت تنظیم)، متن دستورالعمل ادمین، **فقط مبلغ نهایی قابل‌پرداخت**. کارت از secret `PAYMENT_CARD_NUMBER` + سند `payment_info`. |
| **ارسال فیش** | عکس **یا** سند (بزرگ‌ترین نسخه ذخیره؛ caption = شماره مرجع اختیاری ≤۱۲۸). ارسال دوباره در حالت `awaiting_review` جای فیش قبلی را **با audit** می‌گیرد و مجدد فوروارد می‌شود. |
| **پیگیری وضعیت** | توست ثبت فیش؛ پیام نتیجهٔ بررسی (تأیید/رد + دلیل)؛ تاریخچهٔ «سفارش‌های من». |
| **سرویس‌های من** (`menu:services`) | خریدهای تکمیل‌شده با وضعیت محلی (🟢 فعال / ⏳ نزدیک انقضا / ‼️ منقضی)، صفحهٔ جزئیات با غنی‌سازی زنده از پنل و تنزل ایمن به snapshot، دکمهٔ بازکردن صفحهٔ سرویس (لینک پنل). |
| **تمدید** | فقط مدت: preset ماه‌ها (۱/۲/۳، هرگز تایپ آزاد) → خلاصه → همان خط لولهٔ فیش/بررسی **یا** پرداخت کیف‌پولی؛ شارژ فقط جدول مدت؛ تمدید از `max(now, انقضا)`؛ سرویس منقضی هم قابل تمدید؛ booking فقط-روبه‌جلو. |
| **کیف پول** | مشاهدهٔ موجودی؛ پرداخت کامل/جزئیِ سفارش از کیف‌پول؛ اعتبار از اعطای ادمین (بدون شارژ خودکار مشتری)؛ برگشت وجهِ سفارش‌های ردشده به کیف‌پول. |
| **دعوت از دوستان** | کد ۱۲ کاراکتری + لینک `https://t.me/<bot>?start=ref_…`؛ انتساب first-touch در اولین /start؛ پاداش = `reward_percent` اولین خریدِ تأییدشده (شامل اعتبار کیف‌پول) با اعلان؛ سقف عمر به ازای دعوت‌کننده. |
| **تیکت پشتیبانی** | باز کردن (یک تیکت زنده به ازای مشتری)، ادامهٔ گفتگو، relay پاسخ ادمین، بستن؛ ارسال فایل هم پشتیبانی می‌شود. |
| **دریافت اطلاعیه** | broadcast ادمین، یک‌بار برای هر مشتری. |
| **راهنمای اتصال** (`menu:guide`) | پلتفرم (اندروید/iOS/ویندوز) → اپ (v2RayTun و v2rayNG / V2Box و Streisand / Throne) → لینک رسمی + گام‌های یک‌دقیقه‌ای ایمپورت؛ کامل بدون state/DB؛ لینک‌ها زنده راستی‌آزمایی‌شده. |
| **تغییر زبان** (`menu:lang`) | انتخابگر 🇮🇷/🇬🇧 → نوشتن `customers.language` → اعلان و کیبورد فوراً به زبان تازه (انتخاب صریح و ماندگار). |
| **`/start`، `/help`، `/cancel`** | منو/راهنما/بازگشت امن به منو. |
| **تست رایگان (یک‌بار در عمر هر کاربر)** | ۱۰۰ مگابایت / ۱ روز (پیش‌فرض‌های سند `free_test`؛ fail-CLOSED). پیشنهاد فقط در **اولین** `/start` عمر کاربر (حباب جداگانهٔ inline — کیبورد اصلی دست‌نخورده) و در صفحهٔ خالی «سرویس‌های من`. ادعا با `tst:claim`؛ دیوار=DB: PK جدول `free_test_claims` — تپ دوباره، replay، مسابقه و callback جعلی هرگز تست دوم نمی‌سازند (پیش/بین/پس از انقضا). سفارشِ تست یک `purchase` با مبلغ صفر و متولدِ `approved` است (بدون فیش، صف ادمین، یادآور پرداخت و **بدون پاداش دعوت**)؛ با همان قیف پاسارگارد و `data_limit` **بایت‌محور** (۱۰۰MB < کفِ ۱ گیگ نردبان) ساخته می‌شود، با واحد «مگابایت» نمایش داده می‌شود و **هرگز تمدیدشدنی نیست** (guard سمت سرور + مخفی‌بودن دکمه). کلید توقف فروش، ادعای تازه را هم می‌بندد؛ شکِ تأییدشدهٔ درج سفارش فقط claim تازه‌سازِ همان execution را آزاد می‌کند (بازیابی زیر همان order id می‌گراید). |
| **اعلان‌های سرویس** | برای سرویس‌های **پولی**: یک اعلان ۹۰٪ و یک ا انقضای ≤۳ روز در عمر هر سرویس — به زبان گیرنده. تست رایگان *هرگز* این ست را نمی‌گیرد (SQL کانیدیداهای پولی با NOT EXISTS، مسیر تست با EXISTSِ معکوس) و فقط **یک** اعلان `free_test_expiring` ~۲ ساعت پیش از پایان می‌گیرد (همان PK/lease — تكرار cron بی‌اثر؛ اگر کل پنجره از دست برود، بی‌صدا). |
| **یادآور پرداخت** | یادآور مشتری در ≥۱۵/۳۰/۴۵ دقیقه پس از فیش (حداکثر ۳ بار) تا زمان بررسی. |

## امکانات ادمین

| قابلیت | نحوهٔ کارکرد |
| --- | --- |
| **هویت ادمین** | env `ADMIN_CHAT_ID` (تک شناسه عددی) **یا** `customers.is_admin=1`. |
| **صف بررسی فیش** `/pending` | آخرین ۱۰ سفارش `awaiting_review` با ✅/❌؛ فیش‌های رسیده به‌صورت push با همان دکمه‌ها. |
| **تأیید** | تک UPDATE مراقبت‌شده؛ برنده: اطلاع مشتری + پروژن (waitUntil) + تلاش پرداخت پاداش دعوت. |
| **رد** | پرامپت دلیل (TTL ۱۵ دقیقه، متن ≤۲۰۰ sanitize یا «رد با پیش‌فرض»؛ انتقال مراقبت‌شده؛ **برگشت اعتبار کیف‌پول در همان batch**). |
| **صف پروژن‌های ناموفق** `/failed` | آخرین ۱۰ `failed` + دکمهٔ `🔁` (retry با سقف تلاش). |
| **صف تیکت‌ها** `/tickets` | تا ۱۰ تیکت زنده؛ هر ردیف 💬 پاسخ / 👁 جزئیات / ✅ بستن؛ push پیام تازه مشتری با همان ابزار. |
| **اطلاعیه‌ها** `/announce [متن]`، `/announcements` | پیش‌نویس → preview → تأیید → fan-out چانکیِ قابل‌ادامه (دکمهٔ ادامه؛ delivery با PK مرکب ضدتکرار؛ `/announcements` وضعیت ۵ اطلاعیهٔ آخر). |
| **عملیات کیف‌پول** `/credit <id> [مبلغ]`، `/debit …` | arm (مشتری باید ثبت‌نام کرده باشد) → تایپ مبلغ → اعمال مراقبت‌شده/سقف‌دار با نوشتن جفت دفتر کل. |
| **مدیریت قیمت** `/pricing` | نمایش زندهٔ مقادیر + یک دکمه به ازای هر ورودی (فهرست از خود سند ساخته می‌شود) → arm → تایپ عدد (server-side STAGED) → تأیید ✅ → **CAS روی اثرانگشت سند** → تعویض مراقبت‌شده + audit کامل `settings_audit`. |
| **توقف/ازسرگیری فروش** `/sales` | نمایش وضعیت (🟢/🛑 + آخرین تغییر + هشدار سند خراب)، toggle، CAS + audit؛ گیت‌های سمت سرور روی خرید/تمدید/کیف‌پول + backstop داخل checkout ([قیمت‌گذاری](pricing.md)). |
| **digest یادآور (8C)** | یک پیام تجمیعی به ازای هر اجرای sweep با همان دکمه‌های `adm:ok/no` — تأیید از digest دقیقاً همان مسیر guard است. |

## امکانات UX

- پرسونای فارسی از پایه («درود زیبا» در نوتیفیکیشن‌ها) و انگلیسی **اصیل** (نه
  ترجمهٔ کلمه‌به‌کلمه) + قالب‌بندی عدد/تاریخ هر زبان (`i18n.ts`).
- کیبورد reply با دکمه‌های style‌دار (سه‌تای danger/primary/success)، کیبورد حالت «تایپ» برای
  گام‌های متن‌آزاد با ردیف بازگشت.
- پاسخ toast به هر دکمه؛ خنثی‌سازی دکمه‌های مرده روی پیام ادمین پس از بررسی.
- HTML inline-code فقط برای کارت/IBAN/URL (کپی با تپ + راهنمای یک‌بارهٔ «کپی»).
- کیبوردهای مشتری دوزبانه؛ کیبوردهای عملیاتی ادمین عمداً فقط فارسی.

## صریحاً پیاده نشده (تا کسی انتظار نداشته باشد)

- درگاه پرداخت آنلاین / راستی‌آزمایی خودکار واریز — طراحی: دستی.
- شارژ خودکار کیف‌پول توسط مشتری (فقط `/credit` ادمین یا پاداش دعوت).
- چند‌ادمینه بودن `ADMIN_CHAT_ID` (تک id؛ گسترش با `is_admin`).
- مدیریت template و هر تنظیم پنل فراتر از فیلدهای §3 در [PasarGuard](pasarguard.md).
- داشبورد/وب‌سایت/پنل وب ادمین، export آمار، گزارش‌ساز.
- قابلیت گروه/کانال، inline mode، لینک عمیق تبلیغاتی غیر از `ref_`.
- لغو/تیمرِ خودکار سشن فراتر از TTL ۲۴ ساعته؛ ویرایشگر «دستور واریز» داخل ربات.
- هر آیتمِ «Roadmap» سابق که تیک ✅ فاز ۱..۱۳ را ندارد؛ تنها گامباقی‌مانده محصول،
  **عملیات خودِ استقرار/وب‌هوک توسط اپراتور** است (خارج از کد).
